# 核心算法说明：智能床位推荐

> **状态**：本节所述评分权重与画像参数为**原型草案**，用于跑通端到端演示，
> 尚未经过临床/业务确认。正式参数待评审后定稿。
> 实现见 `backend/app/services/recommendation.py`。

## 一、两阶段设计

```
住院证（科室 / 患者性别 / 隔离需求 / 优先级 / 期望病房）
        │
        ▼
┌───────────────────────┐
│ 阶段一：硬约束过滤      │  ← 不可协商，任一不满足即淘汰
│ H1 床位空闲            │
│ H2 科室匹配            │
│ H3 性别限制匹配         │
│ H4 隔离需求匹配         │
└───────────┬───────────┘
            ▼ 候选集
┌───────────────────────┐
│ 阶段二：软约束评分      │  ← 0-100 分，逐项可解释
│ 距离适配        0.32   │
│ 优先级-床型适配  0.28   │
│ 病房负载均衡     0.18   │
│ 成本适配         0.12   │
│ 期望病房         0.10   │
└───────────┬───────────┘
            ▼
      按总分倒序输出，附每项原始分、权重、加权贡献与中文理由
```

## 二、硬约束（`backend/app/services/bed_policy.py`）

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| H1 | 床位状态必须是 `AVAILABLE` | `RESERVED` / `OCCUPIED` / `CLEANING` / `MAINTENANCE` 一律淘汰 |
| H2 | 床位 `department_id` 必须等于住院证科室 | 跨科室分配被拒绝 |
| H3 | `gender_limit` 为 `ANY` 或与患者性别一致 | 性别冲突被拒绝 |
| H4 | 隔离需求双向匹配 | 见 [isolation-bed-policy.md](./isolation-bed-policy.md) |

硬约束在**推荐**与**人工分配**两条路径上共用同一份实现，保证口径一致。

## 三、软约束评分

### 3.1 距离适配（权重 0.32）

床位到科室护士站的加权欧氏距离，楼层差按 `FLOOR_DISTANCE_UNIT = 3` 折算：

```
distance = sqrt( dx² + dy² + (Δfloor × 3)² )
```

**关键点：距离方向随优先级反转**（避免优先级退化成常数分）

| 优先级 | 方向 | 计算 |
| --- | --- | --- |
| 危重 CRITICAL | 越近越好 | `100 - distance × 1.60 × 100/60` |
| 重症 SEVERE | 越近越好 | `100 - distance × 1.35 × 100/60` |
| 急症 URGENT | 越近越好 | `100 - distance × 1.00 × 100/60` |
| 普通 NORMAL | **让出近端** | `55 + min(distance,60)/60 × 45` |
| 轻症 MILD | **让出近端** | 同普通（敏感度 0.55） |

即：危重患者靠近护士站的床位得分高；而轻症/普通患者远离护士站的床位得分高——
把近端资源留给重症。

### 3.2 优先级-床型适配（权重 0.28）

床型适配矩阵 `BED_TYPE_FIT`：

| 优先级 | 监护床 MONITOR | 隔离床 ISOLATION | 普通床 NORMAL |
| --- | --- | --- | --- |
| 危重 | 100 | 86 | 30 |
| 重症 | 94 | 86 | 46 |
| 急症 | 76 | 84 | 72 |
| 普通 | 34 | 84 | 100 |
| 轻症 | 20 | 84 | 100 |

危重/重症患者额外享受楼层修正：1 层 `+9`（危重）/`+6`（重症），3 层及以上等额扣分。

### 3.3 病房负载均衡（权重 0.18）

```
raw = 100 × 该病房空闲床位数 / 该病房总床位数
```

空床率越高的病房得分越高，避免单病房过载。

### 3.4 成本适配（权重 0.12）

```
cheapness = 100 × (max_rate - rate) / (max_rate - min_rate)
raw = 100 - (100 - cheapness) × (1 - cost_sensitivity)
```

成本敏感度随优先级变化：危重 0.30、重症 0.45、急症 0.70、普通 0.90、轻症 1.00。
即危重患者几乎不因费用高低影响排序，轻症患者则明显偏好低价床位。

### 3.5 期望病房（权重 0.10）

命中住院证 `preferred_ward_id` 得 100，未指定取中性值 60，指定但未命中得 55。

### 3.6 总分

```
score = Σ ( raw_i × weight_i )   ，保底 0，封顶 100，保留两位小数
```

排序键：`(-score, distance, bed_id)`——同分时更近者优先，仍同则按 ID 稳定排序。

## 四、可解释性输出

每个候选床位返回：

* `score`：总分
* `score_items[]`：每项 `{key, label, raw_score, weight, contribution, note}`，
  `note` 为中文解释，例如
  「危重患者优先靠近护士站：加权距离 12.5，距离敏感度 ×1.60，得分 66.7」
* `reasons[]`：硬约束通过说明、距离、床型适配、病房负载、成本等自然语言理由
* `warnings[]`：提示性风险，如「监护床资源紧张，轻症/普通患者占用会挤占重症资源」
  「楼层偏高，危重患者转运时间较长」「该病房仅剩 1 张空床」

## 五、无合适床位时的原因说明

返回 `recommendations: []`，并在 `no_result_reasons` 中给出可定位的原因，
配合 `hard_constraint_stats` 的分层排除计数：

| 场景 | 原因文案示例 |
| --- | --- |
| 科室无床位配置 | 科室「心血管内科」尚未配置任何床位，无法分配。 |
| 全部被占用 | 科室「心内科」当前没有任何空闲床位：共 26 张（空闲 1 张、预占用 3 张、已入住 20 张、清洁中 2 张）。 |
| 隔离床不足 | 患者需要隔离，但科室「心血管内科」当前 5 张空闲床位全部为普通床，没有可用隔离床（策略 P5：不降级到普通床）。 |
| 隔离床不对外开放 | 科室「感染性疾病科」的空闲床位全部为隔离床。按策略 P2，隔离床只对隔离患者开放，非隔离患者不得占用。 |
| 性别冲突 | 科室存在空闲普通床 8 张，但其中 8 张的性别限制与患者（男）冲突（H3）。 |

`hard_constraint_stats` 字段：

```json
{
  "department_total_beds": 11,
  "department_available_beds": 5,
  "candidates_after_status": 5,
  "excluded_by_status": 6,
  "excluded_by_isolation": 2,
  "excluded_by_gender": 3,
  "status_breakdown": {"AVAILABLE": 5, "OCCUPIED": 4, "RESERVED": 1, "CLEANING": 1, "MAINTENANCE": 0}
}
```

## 六、优先级为何不是「每张床相同的常数分」

同一张床对不同优先级患者会得到明显不同的分数与排序：

| 床位 | 危重患者得分 | 轻症患者得分 | 差异来源 |
| --- | --- | --- | --- |
| 监护床（距护士站 2） | 高（距离×1.6 + 床型 100 + 低楼层加分） | 低（距离反向 + 床型 20） | 距离方向 + 床型矩阵 + 楼层修正 |
| 普通床（距护士站 40，¥100） | 低（距离×1.6 重罚 + 床型 30） | 高（距离反向 + 床型 100 + 成本满分） | 距离方向 + 床型矩阵 + 成本敏感度 |

因此 `PRIORITY_RANK` 不是被加成一个固定常量，而是通过
`PRIORITY_PROFILE`（距离模式、距离敏感度、成本敏感度、楼层加分）
与 `BED_TYPE_FIT`（床型矩阵）两处参与计算，改变的是**排序本身**。

## 七、复杂度

设科室床位数为 `n`，病房数为 `m`：硬约束过滤 `O(n)`，评分 `O(n)`，排序 `O(n log n)`，
整体近似 `O(n log n)`。单科室床位规模下（数十张）无需索引优化，
也**不需要** OR-Tools 等全局优化求解器。
