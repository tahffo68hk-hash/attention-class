# 本地 P0 浏览器验收用例（须真实执行，不能提前标 PASS）

1. admin 登录，进入首页，看板数量与 MySQL 实际分组一致。
2. 医生创建住院证，办理预登记后待入院队列出现该申请。
3. 用 CRITICAL/SEVERE/URGENT/NORMAL/MILD 五档构造测试，验证队列顺序与登记先后。
4. 对隔离患者与非隔离患者分别生成推荐；普通床和隔离床严格分开。
5. 展开五维评分明细，核对总分 0–100、进度条比例及距离/成本解释。
6. 管理员手工选冲突床，应被后端 422 拒绝；无候选时有具体原因。
7. 两个管理员抢同一床、同一住院证抢两床，MySQL 并发用例验证只有一个成功。
8. 一次预占的同一 Idempotency-Key 重试得到同一 allocation id，不生成新的记录；异参 409。
9. 预占后换床（新床可用）成功，旧床释放、日志与记录一致；向不可用床换床必须完整回滚。
10. 预占→入住→出院：床位进入 CLEANING，再调用 release 变 AVAILABLE，历史记录留存。
11. 审计列表筛选时间范围；床位状态流水显示真实操作人。
12. 观察员尝试敏感操作，应收到 403；患者列表敏感字段应脱敏。
13. 控制台无异常，前端 production build 与后端测试通过。
14. 注意演示数据重置会清空业务库；不能在含任何需要保留的数据的库中执行 `seed.py`。
